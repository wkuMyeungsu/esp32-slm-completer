기존 모델 비교

ESP32-S3 보드에서 Python 자동완성을 하려고 검토한 공개 모델들의 장단점과, 이 프로젝트에 맞는 점을 정리했다. (2026-11-03 기준)

이 프로젝트가 모델에 요구하는 것

조건이유
float32 약 6MB 이하가중치는 플래시 model 파티션(6MB)에 굽고 부팅 때 PSRAM(8MB)으로 읽는다. PSRAM에는 KV 캐시 1.5MB도 함께 올라간다.
표준 구조추론을 C로 직접 짜서 보드에 넣는다. 원격 코드(trust_remote_code)가 필요한 구조는 옮기고 맞춰 보기가 어렵다.
사전학습에 코드 포함코드를 본 적 없는 모델은 적은 데이터로 코드를 배우기 어렵다.
임베딩을 줄일 수 있을 것쓰는 토큰만 남기면 크기가 크게 준다. 토큰마다 가중치 전부를 PSRAM에서 읽으므로 크기가 곧 속도다.

Pythia-14M이 이 프로젝트에 맞은 점과 안 맞은 점

맞은 점

  • 조건 네 가지를 모두 만족한 유일한 후보였다.
  • 표준 구조라 C와 numpy로 직접 옮겼고, torch와 로짓 최대 오차 5.91e-05로 맞는다.
  • 입력·출력 임베딩이 분리돼 있어 쓰는 토큰 1,012개만 남기면 5.8MB다. KV 캐시와 함께 PSRAM에 들어가고 1,188,740 B가 남는다.
  • 2,000스텝 학습이 약 2분이라 데이터를 바꿔 여러 번 시도할 수 있었다.

안 맞은 점

  • 핵심부가 작아 학습 뒤에도 처음 보는 쉬운 코드에서 줄 중간 정확 일치 0.117, 줄 시작 0.027이다.
  • 어휘를 1,012로 줄이면 처음 보는 코드의 입력 토큰 23%가 더 작은 토큰으로 쪼개져 길어지고, 보드 시간이 늘어난다 (토큰당 119 ms).
  • 같은 줄을 다시 쓰는 습관이 남아 있다 (실사용에서 # Replace를 줄마다 제안).
